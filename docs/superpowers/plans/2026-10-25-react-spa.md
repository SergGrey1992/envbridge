# React SPA и документация Next.js: план реализации

Цель: тот же пакет, runtime.config.ts и client getters для обычного React18/19 без обязательного Next.js. Пример и browser-проверки на Vite7; существующие интеграции Next13–16 сохраняются.

## Решение
Общие Node функции сериализации/handler/script находятся в /runtime без React/Next imports. /next использует это ядро и сохраняет все экспорты. Next становится optional peer. Для SPA команда bootstrap пишет только public snapshot в classic JS, подключаемый до module entry; её выполняют при запуске/развёртывании, не при каждой React render. Generate по-прежнему пишет только имена в TS и пустые env templates. Bootstrap явно отделён от generate, потому что JS содержит фактические публичные значения.

CLI: next-runtime-env bootstrap [--cwd] [--config] [--dotenv file] [--output ./public/runtime-env.js]. По умолчанию только process.env, env-file читается явно через Node loadEnvFile. Bootstrap не загружает Next/Vite dotenv автоматически. Вывод JS проверяет root/symlink/hardlink/generated marker и использует атомарную установку. В SPA нет Server Components: server.ts остаётся Next-only, секреты принадлежат backend.

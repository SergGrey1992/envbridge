# Пример проверки runtime env

На главной странице показываются все публичные ключи сгенерированного client env. Значения `undefined` и пустая строка отображаются отдельно. APP_NAME также читается в Server Component для сравнения SSR и клиентского результата.

При открытии главной страницы Server Component выводит фактические значения JWT_SECRET и DATABASE_URL в терминал процесса Next.js с меткой `[next-runtime-env example] Server-only variables:`. Запись идёт напрямую в stdout: console.log из Server Components Next.js может пересылать в браузер в dev-режиме. В браузер эти значения не передаются. Это явное диагностическое логирование только данного примера; сама библиотека значения не логирует.

Заполните .env до запуска сервера. `generate` добавляет пустые ключи, а не значения. После изменения .env перезапустите сервер. Если используете production build, после изменения исходников примера сначала повторите `npm run build`.

При output: standalone используйте `node .next/standalone/server.js`, скопировав .next/static в .next/standalone/.next/static. Значения передавайте окружению standalone процесса; .env из корня проекта не следует считать автоматически доступным в отдельной standalone директории. Для простого локального запуска с .env можно использовать `npx next dev`.

RootError, Missing и NotFound в навигации — намеренные проверки страниц ошибок.

# Пример проверки runtime env

На главной странице показываются все публичные ключи сгенерированного client env. Значения `undefined` и пустая строка отображаются отдельно. APP_NAME также читается в Server Component для сравнения SSR и клиентского результата.

При открытии главной страницы Server Component выводит фактические значения JWT_SECRET и DATABASE_URL в терминал процесса Next.js с меткой `[next-runtime-env example] Server-only variables:`. Запись идёт напрямую в stdout: console.log из Server Components Next.js может пересылать в браузер в dev-режиме. В браузер эти значения не передаются. Это явное диагностическое логирование только данного примера; сама библиотека значения не логирует.

Заполните .env до запуска сервера. `generate` добавляет пустые ключи, а не значения. После изменения .env перезапустите сервер. Если используете production build, после изменения исходников примера сначала повторите `npm run build`.

При output: standalone используйте `node .next/standalone/server.js`, скопировав .next/static в .next/standalone/.next/static. Значения передавайте окружению standalone процесса; .env из корня проекта не следует считать автоматически доступным в отдельной standalone директории. Для простого локального запуска с .env можно использовать `npm run dev`.

RootError, Missing и NotFound в навигации — намеренные проверки страниц ошибок.

## Подготовка локальной зависимости

Пример использует локальный tarball библиотеки. После обновления исходников старый установленный пакет может не содержать новых exports. Теперь `npm run build` и `npm run dev` автоматически собирают свежий tarball и обновляют установленный пакет библиотеки, используя уникальный временный путь вместо кешированного архива с тем же именем. Также сбрасывается сборочный кеш Next.js, который мог сохранить старые exports пакета. `.env` и его значения не изменяются.

Для ручного обновления выполните `npm run prepare:example` из корня репозитория. Затем в examples/next-app запускайте `npm run build` либо `npm run dev`. В Docker с готовым tarball подготовка лишь проверяет наличие актуального export, без повторной сборки библиотеки.
